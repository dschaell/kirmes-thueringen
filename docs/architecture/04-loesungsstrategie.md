# 4. Lösungsstrategie

| Ziel / Anforderung         | Lösungsansatz                                                                                                                                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Wartbarkeit                | **Clean Architecture** im Server-Tier: Fachlogik in `packages/core` ohne jede Laufzeit-Abhängigkeit; Adapter (HTTP, PostgreSQL) hängen vom Core ab, nie umgekehrt (**Dependency Inversion**). Durchgesetzt mit dependency-cruiser + ESLint in CI. |
| N-Tier                     | Drei getrennt deploybare Container: `web` (Astro-SSR, Node.js), `api` (Node.js), `db` (PostGIS).                                                                                                                                                  |
| Sicherheit                 | Defense in Depth: Validierung im Core, statisches SQL mit Parametern, Security-Header, Secret-, SAST-, SCA- und DAST-Gates in jeder Pipeline.                                                                                                     |
| Korrektheit                | Domänenvalidierung mit `Result`-Typen statt Exceptions; Kennzeichen `bestaetigt` für hochgerechnete Termine.                                                                                                                                      |
| Auffindbarkeit/Performance | Statisch generiertes Frontend (Astro): eine HTML-Seite pro Ort, schema.org-Events, Sitemap.                                                                                                                                                       |
| Geodaten                   | PostGIS `geography(Point, 4326)` + GiST-Index; Koordinaten einmalig per OSM-Geocoding.                                                                                                                                                            |
| Schlankheit                | Wenige, etablierte Bibliotheken (Fastify, pg, Astro); kein ORM – SQL bleibt sichtbar und reviewbar.                                                                                                                                               |
