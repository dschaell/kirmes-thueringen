# 4. Lösungsstrategie

| Ziel / Anforderung            | Lösungsansatz                                                                                                                                                                                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Wartbarkeit                   | **Clean Architecture** im Server-Tier: Fachlogik in `packages/core` ohne jede Laufzeit-Abhängigkeit; Adapter (HTTP, PostgreSQL) hängen vom Core ab, nie umgekehrt (**Dependency Inversion**). Durchgesetzt mit dependency-cruiser + ESLint in CI. |
| N-Tier                        | Drei getrennt deploybare Container: `web` (Astro-SSR, Node.js), `api` (Node.js), `db` (PostGIS).                                                                                                                                                  |
| Sicherheit                    | Defense in Depth: Validierung im Core, statisches SQL mit Parametern, Security-Header, Secret-, SAST-, SCA- und DAST-Gates in jeder Pipeline.                                                                                                     |
| Korrektheit                   | Domänenvalidierung mit `Result`-Typen statt Exceptions; Kennzeichen `bestaetigt` unterscheidet Veranstalter-Angaben von recherchierten Terminen.                                                                                                  |
| Auffindbarkeit/Performance    | Statisch generiertes Frontend (Astro): eine HTML-Seite pro Ort, schema.org-Events, Sitemap.                                                                                                                                                       |
| Geodaten                      | PostGIS `geography(Point, 4326)` + GiST-Index; Koordinaten einmalig per OSM-Geocoding.                                                                                                                                                            |
| Schlankheit                   | Wenige, etablierte Bibliotheken (Fastify, pg, Astro); kein ORM – SQL bleibt sichtbar und reviewbar.                                                                                                                                               |
| Datenhaltbarkeit              | Ergänzende Migrationen (Sperre im Lint), Upgrade-Test in der CI, Sicherung vor jedem Update, tägliche Dumps mit Status in der Redaktion, optionale verschlüsselte Offsite-Kopie.                                                                  |
| Zugriffsschutz                | Rollenmodell mit einer einzigen Quelle (`rechte.ts`): Admin, Redaktion, Kirmesgesellschaft (nur eigener Ort). Anmeldung ausschließlich mit Passkey, Einladungen als Einmal-Token.                                                                 |
| Reproduzierbarkeit            | Alles in Docker: Betriebsdienste, Entwicklung (`dev`), Werkzeuge (`tools`) und das Quality Gate (`check`) laufen in Containern mit gleicher Node-Version (ADR 025).                                                                               |
| Betrieb ohne Zugang von außen | GitOps: Der Server holt sich neue Versionen selbst (Merge auf `main`), keine eingehende Verbindung für Deployments nötig.                                                                                                                         |
| Mobile Nutzung                | Server-gerenderte Seiten mit wenig JavaScript, Suche als GET-Formular ohne JavaScript, installierbar auf dem Home-Bildschirm, Karte nur auf der Kartenseite.                                                                                      |
| Datenschutz                   | Kein Tracking, keine Cookies außer Formularschutz, Zählung ohne IP, Bildmetadaten werden entfernt, Karten erst nach Aufruf der Kartenseite.                                                                                                       |
| Konfiguration                 | Ausschließlich Umgebungsvariablen; halbe Konfigurationen (SMTP, VAPID) sind Startfehler.                                                                                                                                                          |
